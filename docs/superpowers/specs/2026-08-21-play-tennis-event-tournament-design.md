# Play Tennis 이벤트 대회 설계

## 목적

기존 멀티클럽 테니스 대회 프로그램에 `Play Tennis` 클럽(`/pt`)을 일반 클럽으로 추가한다. Play Tennis는 회원관리와 모든 기존 대회 방식을 계속 사용할 수 있어야 한다. 이와 별개로 `2026-08-22`에 열리는 `제2회 임진강 나룻배`만 확정 대진을 사용하는 일회성 이벤트 대회로 등록하고, 관리자는 대진을 변경하지 못한 채 점수만 입력할 수 있게 한다.

기존 STC, OTC, 주고받고, 천하제일1사단, 퀸즈데이와 기존 대회 동작에는 변화가 없어야 한다.

## 핵심 결정

별도 이벤트 페이지를 복제하지 않는다. 공통 화면과 저장소에 대회별 정책을 추가하고, 정책의 기본값을 기존 동작과 동일하게 둔다. 이벤트 대회 여부를 클럽 슬러그나 대회 이름으로 하드코딩하지 않고 DB의 대회 설정으로 판정한다.

이 방식은 점수 입력, 공개 대진표, 실시간 순위 같은 검증된 공통 기능을 그대로 재사용하면서도 이벤트 예외를 작은 정책 경계 안에 가둔다. 정책 판정은 순수 함수로 분리하고 UI와 서버 양쪽에서 동일하게 적용한다.

## 클럽 구성

- 슬러그: `pt`
- 이름과 짧은 이름: `Play Tennis`
- 조직 유형: 기존 테니스 클럽과 동일한 `클럽`
- 관리자 비밀번호: 기존 기본 비밀번호 `1234`
- 회원관리, 대회 생성, KDK-V2010, 한울AA KDK, 랜덤 KDK, 고정페어리그, 청백전, 토너먼트 등 기존 기능을 모두 제공한다.
- 향후 Play Tennis에서 생성하는 일반 대회에는 이벤트 정책을 적용하지 않는다.

## 이미지

기존 OTC 인트로 이미지와 카카오톡 공유 이미지를 기준으로 새 자산을 만든다. 배경, 비율, 전체 구성은 유지하고 `OTC` 명칭만 `Play Tennis`로 교체한다.

- 인트로 이미지: `public/pt_intro_summer_coast.webp`
- 카카오톡 공유 이미지: `public/kakao-share-pt.jpg`

클럽 설정, 스플래시 이미지 매핑, 카카오톡 공유 콘텐츠에 `pt`를 추가한다.

## 대회별 정책 모델

`Tournament`에 다음 필드를 추가한다.

- `scheduleLocked Boolean @default(false)`: 참가자, 그룹, 대진방식, 대진 생성, 선수 배치, 경기 추가·삭제·순서 변경을 잠근다.
- `rankingExcludedMemberIds String[] @default([])`: 해당 대회의 순위표에서 제외할 회원 ID 목록이다.
- `includeInClubRecords Boolean @default(true)`: 연도별 클럽 기록 통계 포함 여부다.

확정 대진의 라운드를 손실 없이 표시하기 위해 `Match`에 `roundNumber Int?`를 추가한다. 기존 경기의 기본값은 `null`이며 표시 방식도 바뀌지 않는다. 값이 있는 경기만 관리자와 공개 대진표에서 라운드별로 묶는다.

도메인 `Tournament` 타입에도 같은 값을 선택적 필드로 추가하고, 값이 없는 기존 데이터는 각각 `false`, 빈 배열, `true`로 해석한다. 따라서 기존 대회의 동작은 변경되지 않는다.

정책 판정은 별도 순수 함수 모듈에 둔다.

- 대진 구조 편집 가능 여부
- 점수 편집 가능 여부
- 순위 대상 회원 필터링
- 클럽 기록 포함 여부

## 이벤트 대회 데이터

- 대회명: `제2회 임진강 나룻배`
- 일시: `2026-08-22`
- 대회 유형: 일반대회
- 그룹: 1개
- 내부 대진 형식: 기존 `random` 형식을 사용하되 잠긴 대회 화면에서는 형식명과 생성 설정을 노출하지 않는다.
- 참가자: 확정 명단 32명
- 대진: 확정된 8라운드, 라운드당 4코트, 총 32경기
- 경기 점수 초기값: 미입력
- `scheduleLocked`: `true`
- `rankingExcludedMemberIds`: 유태주, 감독진의 회원 ID
- `includeInClubRecords`: `false`

회원 이름, 성별, 레벨과 경기 배치는 아래 확정 명단과 대진을 사용한다. `유태주`를 정식 표기로 사용한다.

데이터는 기존 운영 데이터를 삭제하는 `db:seed`가 아니라 재실행 가능한 추가형 Prisma 마이그레이션으로 넣는다. 고정 ID와 `ON CONFLICT` 처리를 사용해 배포 재시도 시 중복 생성되지 않게 한다.

## 관리자 화면

Play Tennis의 일반 대회 화면은 기존과 동일하다.

확정 이벤트 대회에서는 다음만 제공한다.

- 첫 진입 탭은 `대진표`
- 대진표 조회
- 0~6점 점수 입력, 저장, 수정 및 초기화
- 순위 조회
- 공유하기

다음 기능은 숨기거나 비활성화한다.

- 대회 설정 탭
- 대회명과 날짜 변경
- 참가자 변경
- 그룹 추가·삭제 및 편성 변경
- 대진방식 변경
- 대진표 재생성
- 경기 추가·삭제
- 선수 변경
- 경기 및 라운드 순서 변경
- 대회 삭제

잠긴 대회에서도 점수 저장은 기존 경기별 점수 액션을 그대로 사용한다. 전체 대회 상태를 교체하는 저장 경로는 사용하지 않는다.

## 서버 보호

화면에서 버튼만 숨기는 것으로 끝내지 않는다.

- 전체 대회 상태 저장 액션은 DB의 `scheduleLocked`를 조회하고, 잠긴 대회의 구조 변경 요청을 거부한다.
- 대회명 변경, 날짜 변경, 대회 삭제 액션도 잠긴 대회에서는 거부한다.
- 경기 점수 입력과 점수 초기화 액션만 허용한다.
- 모든 판정은 클라이언트가 보낸 잠금 값이 아니라 서버가 DB에서 읽은 값을 기준으로 한다.

## 순위와 기록

순위 계산 전에 그룹 회원 중 `rankingExcludedMemberIds`에 포함된 회원만 제거한다. 경기 데이터 자체는 제거하지 않는다.

따라서 유태주와 감독진이 참여한 경기 결과는 다음과 같이 처리된다.

- 유태주와 감독진은 순위 카드에 나타나지 않는다.
- 두 선수의 파트너는 승·무·패, 승점과 득실을 정상 반영한다.
- 상대 선수도 경기 결과를 정상 반영한다.

공개 화면과 관리자 화면이 같은 필터 함수를 사용해 순위가 일치하게 한다.

연도별 기록 조회에서는 `includeInClubRecords = false`인 대회의 경기 전체를 제외한다. 이번 이벤트 공개 화면에서는 기록 통계 이동 버튼도 숨긴다. 향후 Play Tennis의 일반 대회는 기본값 `true`로 기록에 포함된다.

## 공개 화면

공유 화면은 기존 공개 대진표와 실시간 순위 UI를 재사용한다.

- 확정된 8라운드와 코트 번호를 표시한다.
- 점수 저장 후 기존 새로고침 및 5분 자동 갱신으로 반영한다.
- 순위표에서는 유태주와 감독진을 제외한다.
- 이번 이벤트에서는 연도별 기록 링크를 표시하지 않는다.
- 완료 날짜가 지나도 기존 요구사항대로 공개 대진표와 순위는 계속 조회할 수 있다.

## 회귀 방지

기존 기능 보호를 위해 다음 테스트를 추가한다.

- `pt`가 유효한 클럽 슬러그로 인식되고 모든 기존 경로가 생성되는지 확인한다.
- 정책 필드가 없는 기존 대회가 편집 가능하고 기록에 포함되는지 확인한다.
- 잠긴 대회에서 구조 변경 액션은 실패하고 점수 액션은 성공하는지 확인한다.
- 제외 회원 본인만 순위에서 빠지고 파트너와 상대 결과는 유지되는지 확인한다.
- 기록 제외 대회의 경기가 연도별 기록 집계에서 빠지는지 확인한다.
- 일반 Play Tennis 대회는 기존 대회 생성과 편집 기능을 그대로 사용하는지 확인한다.
- 기존 클럽의 화면·공개 링크·순위·기록 테스트를 전체 실행한다.
- Prisma 마이그레이션, 타입 검사, 프로덕션 빌드와 모바일 화면 확인을 수행한다.

## 배포

1. Prisma 스키마와 추가형 마이그레이션을 배포한다.
2. 애플리케이션 코드와 이미지 자산을 배포한다.
3. `/pt`, `/pt/login`, `/pt/tournaments`, 이벤트 관리자 화면과 공개 공유 URL을 확인한다.
4. 대표 경기 한 건에 점수를 입력하고 공개 순위 반영을 확인한 뒤 초기화한다.
5. 기존 클럽 대표 경로와 대회 관리 화면을 점검한다.
